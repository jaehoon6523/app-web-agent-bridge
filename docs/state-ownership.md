# 작업과 웹 세션의 소유권

이 문서는 한 번에 하나의 CODE_CHANGE 런과 하나의 인증된 확장 연결을 운영하는 현재 계약을 기록한다. 프로젝트별 기록은 여러 개일 수 있지만 동시 실행 권한은 늘어나지 않는다.

| 사실 | 소유자 | 재연결 시 처리 |
| --- | --- | --- |
| 런 단계, 후보, 감사 결과, 적용 여부 | `CodeChangeStore` / `CodeChangeService` | 저장된 버전과 이력을 검증한 뒤 복구 |
| 정확한 웹 대화·탭 바인딩 | `WebExtensionTransport`와 확장의 탭 저장소 | 실행 전에 정확한 ID와 문서를 다시 확인 |
| 확장 연결 인증과 생존 | `WebExtensionTransport` | 최근 메시지 또는 heartbeat 후 65초가 넘으면 새 연결을 허용 |
| 전송 완료 여부 | Controller의 delivery 기록과 확장의 전송 증거 | 확인할 수 없으면 미확정으로 보존하고 자동 재전송 금지 |
| 프로젝트별 작업 목록 | Controller의 저장된 런 | 같은 대상 경로로 묶어서 표시 |

확장이 20초 간격으로 보내는 heartbeat는 **연결 생존**만 증명한다. 메시지 전송 성공이나 ChatGPT 응답 완료를 증명하지 않는다. 오래된 소켓을 교체하면 이전 소켓의 `close`는 새 소켓을 제거할 수 없으며, 진행 중이던 전송은 별도 증거 없이 성공이나 재시도 가능 상태로 바뀌지 않는다.

Forge의 작업 관리, OpenBrowser의 연결 방식, Kelruno의 증거·승인 패턴을 추가할 때도 위 각 사실의 소유자를 하나로 유지한다. 기능을 추가하기 전에 해당 상태의 저장 위치, 재시작 후 복구 기준, 사용자에게 보일 실패 상태를 정한다.
