## 조작을 줄이기 위한 세부 UX 기준안

아래는 제품 동작 제안이다. 사용자가 요청한 동작만 자동화하고, 신원·대화 귀속·재전송·승인에 의사결정이 필요한 때에만 조작을 요청한다. ‘0회’에는 폼 입력이나 정상 사용자가 선택한 새 작업 시작을 포함하지 않는다.

| 상태 | 시스템이 먼저 해야 할 일 | 사용자가 해야 할 일 | 목표 조작 |
| --- | --- | --- | --- |
| 서버 응답 지연 | 화면의 초안을 보존하고 읽기 상태 표시 | 기다리거나 필요할 때만 다시 확인 | 정상 회복 0회 |
| 서버 재시작·대시보드 세션 만료 | 연결 복구 후 브라우저 세션 갱신과 상태 재조회 | 별도 로그인 조작 없음 | 0회 |
| 확장 인증됨 | 안내를 갱신하고 새 작업이 가능하면 활성화 | 필요 시 요청·폴더 입력 | 추가 연결 조작 0회 |
| 확장 미연결 | 현재 차단 사유와 가능한 연결 동작 한 곳에 표시. 자동 재연결 여부는 실제 상태로 구분 | 자동 복구에 실패했을 때만 연결 도움 선택 | 0회 또는 1회 |
| 서버 주소 불일치 또는 확장 인증 정보 오류 | 서버에 실제 확인된 실패 종류가 있을 때 해당 진단을 표기. 미관측이면 범위를 명시 | 표시된 설정을 한 번 확인 | 하나의 다음 행동 |
| 다른 확장 신원 | 이미 알고 있는 신원과 인증 후보를 구별하고 명시적 승인 유지 | 후보 확인·승인 | 필요한 승인 유지 |
| 인증됨 + 새 대화 시작 | URL 공란을 시작 URL로 정규화하고 기존 계보·재사용 값 없이 전송 | 요청과 폴더 지정 후 시작 클릭 | 필수 두 값 + 클릭 1회 |
| 시작 탭 자동 선택 가능 | 검증된 유휴 시작 탭 사용 또는 정상 창에 자동 생성 | 탭 조작 없음 | 0회 |
| 시작 탭 선택 필요 | 서버가 확인한 후보만 보이고 해당 후보를 선택하면 다음 상태가 명확하도록 설명 | 정확한 탭 선택과 전송 의도 확인 | 필요한 대상 선택 유지 |
| 전송 예약·탭 확인 | 아직 전송하지 않은 단계 표시 | 대기 | 0회 |
| 전송 확인·응답 대기 | 확인된 경우에만 전송 완료 표시. 준비 ID는 같은 요청에 연결 | 대기 | 0회 |
| 전송 결과 미확정 | 재전송 없이 영수증과 현재 소유권 조회. 새 작업의 폼을 덮지 않음 | 결과를 읽지 못한 경우에만 복구 동작 선택 | 자동 확인 0회 |
| 응답 검증·ACK | 증거와 ACK가 모두 확인될 때만 저장 완료 표시 | 대기 | 0회 |
| 대화 ID·매핑 저장 완료 | 준비 요약에서 대화 열기 제공. 전체 ID와 원본 정보는 상세에서 확인 | 대화를 보려면 ‘대화 열기’ | 선택 1회 |
| 요구사항 승인 | 확장 인증·응답 저장과 분리해서 승인 버튼 표시 | 현재 요구사항의 구현 여부 선택 | 명시 승인 유지 |
| 프로젝트/원본 대화 사용 | 유효한 기존 주소와 출처를 제시. 새 대화는 입력 없이 가능 | 기존 주소를 쓰려는 경우만 선택 | 기본 새 대화 선택 0회 |

검증 시 화면 요소의 개수보다 목표 달성까지 필요한 입력·클릭을 센다. 정상 신규 흐름은 `요청 입력 → 폴더 지정 → 시작`이다. 재조회 버튼은 결과 검증용으로 쓸 수 있고 정상 흐름의 필수 단계가 되지 않는다. 연결 상태 안내, 전송 상태 안내, 대화 바로가기는 각각 독립적으로 재현·검증할 수 있다. 우선순위와 수용 기준은 제안으로 남긴다.
