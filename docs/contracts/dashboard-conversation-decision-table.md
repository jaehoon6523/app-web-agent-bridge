## 입력과 판정 순서

작업 유형은 새 작업과 이어서 작업이다. 프로젝트 매핑은 없음, 정상(표준 정확 URL과 일치하는 ID), 불완전(값 누락·오류·불일치), 변경됨(조회 이후 값 변경)으로 나눈다. 원본 Run URL은 없음/있음이며, 체크는 선택/해제/숨김이다. 숨김은 전송상 false이고 체크박스 속성이 disabled로 바뀐다는 뜻은 아니다. URL은 공란/표준 시작/정확 대화/잘못된 값이다. 바인딩은 미생성/준비/확인 완료/실패다.

조합은 아래 ①의 폼 초기화, ②의 제출·서버 수락, ③의 바인딩 결과를 순서대로 합성한다. `—`는 해당 입력 축이 그 단계 판정을 바꾸지 않음을 뜻한다. 미선택으로 원하는 정확 URL을 직접 입력한 경우에도 ②의 명시적 기존 대화 행을 적용한다. ③은 유효한 시작을 접수한 경우에만 적용한다.

| RULE-05/06 | 정확 URL 또는 표준 시작 URL / 선택 / ID 없음 또는 현재 URL 다름 | 유효 URL 검증 뒤 각각 409 `PROJECT_CONVERSATION_UNAVAILABLE` / `PROJECT_CONVERSATION_CHANGED`. 렌더 전 캡처한 편집 값이나 이전 매핑 값도 동일 대조 | 기존 준비·Run·매핑 유지. 새 대화로 자동 전환하지 않음 |
| RULE-05 | 정확 URL / 선택 / 저장 레코드의 truthy ID가 URL ID와 불일치하지만 URL 문자열 일치 | 시작 시 저장 ID 자체의 형식·동일성까지 비교하지 않아 수락 가능. 실제 바인딩은 입력 URL 기준 | 잘못된 매핑 ID 자체를 상속하지 않음. 잘못된 대화 선택 위험. 이상값이 표준 루트이면 정확 문자열 수락 후 신규 분기까지 가능(정적) |
| RULE-05/08 | 정확 URL / 해제 또는 숨김 / 정상·불완전·삭제 여부 무관 | `reuseProjectConversation:false`. 서버는 매핑 대조 없이 202 가능 | 기존 URL 사용. 현행 소스 URL 자동입력도 이 행에 속함. 새 대화 없음. 이후 ACK 성공 시 현재 프로젝트 매핑을 덮어쓸 수 있음 |
| RULE-05/08 | 시작 형태 `https://chatgpt.com//` 또는 정확 URL 끝 `/` / — | 현행 입력 정규식 통과 가능. 신규 판정은 표준 URL 문자열 한 종류이고, 기존 ID 도출은 마지막 슬래시 구간 | 빈 ID가 된 입력은 정확 바인딩 검증을 통과할 정상 대화가 아님. 이 문자열 조합의 실제 HTTP 이후 결과 `NOT_RECORDED` |

| RULE-09 | 양쪽 / 모든 조합 / 런타임 미확인 또는 활성 준비·Run | FE 게이트로 시작 금지. 직접 API도 서버 게이트 확인. 승인 전 `resultingRunId:null`은 정상 | 진행 중 준비·활성 전송/기록을 그대로 유지. 불명확한 POST에는 영수증 조회 |

## ③ AS-IS 바인딩과 보존

| RULE | 새 대화 상태 | UI·API·저장 결과 |
| --- | --- | --- |
| RULE-08 | 미생성 | 표준 시작 요청의 준비 ID 생성 뒤도 세션 URL/ID null · `UNBOUND`. 이전 매핑 유지 |
| RULE-08 | 준비 | 최초 bootstrap의 `createNewConversation`는 준비 서비스가 보냄. 검증 범위에서 시작 탭 1개 재사용, 0개면 안전한 정상 창이 결정될 때 열기, 2개 이상 또는 inventory 변경은 차단/사용자 선택. `ROOT_READY`에서는 ID null |
| RULE-08 | 확인 완료 | 새 정확 URL·ID는 전송 후 BOUND에서 관측되어 준비에 저장. 검증·ACK 완료 트랜잭션에서만 매핑 갱신. 기존 주소 분기도 같은 커밋에 도달할 수 있음 |
| RULE-09 | 실패·취소·복구 | 미전송 실패는 `WEB_BLOCKED` 등, 불확실한 전송은 `RECOVERY_REQUIRED`. 매핑은 마지막 성공 커밋 값 유지. 원래 전달·응답·진단을 보존하고 재전송을 가정하지 않음. 사용자 취소로 성공한 과거 매핑을 지우지 않음 |
| RULE-09 | 중복·경합 | 같은 요청 ID/본문 영수증과 준비 버전 및 전송 소유권 검사. 승인 예약 ID 재사용. 쓰기 미확정은 재시도 중 같은 실행을 대조하며 새 ID를 가정하지 않음 |

P의 신규 테스트에서 최신 매핑이 사라진 후 남은 URL이 실제 FE POST body에 false 플래그로 캡처됐다. H는 서버가 현재 보유한 매핑과 오래된 URL이 다를 때 409를 내는 것을 확인했다. 다른 준비의 응답이 실제 외부 브라우저에서 도착하는 전체 경합의 재현은 `NOT_RECORDED`다.

| D-1 | 정상 프로젝트 매핑 자동 우선, 없으면 이어서 폼에 원본 URL 자동입력 가능. 서버는 원본과 URL을 별개 처리 | 프로젝트 우선은 최근 팀 맥락을 따르나 원본 메시지 귀속과 다를 수 있다. 원본 우선은 작업 계보가 직관적이나 현재 프로젝트 대화와 분리된다. 명시 선택은 외부 메시지 도착점을 확인할 수 있고 조작이 추가된다 | 명시 선택 우선. 옵션마다 출처와 URL을 보이고, 최초 추천과 확정 선택을 구분 | 자동화 감소.
