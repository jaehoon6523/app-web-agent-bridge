# UI 변경 이후 검증 계약 보완

기준 커밋: `64d557fecd4c02cb80c272d5e629c064ff726f37`.

## 목표와 변경

- 툴바 팝업에서 같은 상태를 보여주는 별도 크기 조절 창을 연다. 창 모드는 쿼리 인자의 순서나 추가 인자에 의존하지 않는다.
- UF-12는 Chrome 탭 생성 결과의 ID를 선택한다. 관계없는 탭을 먼저 만들어 생성 순서가 달라도 동작하는지 확인하며, 선택만으로는 전송되지 않고 선택하지 않은 후보에는 전송하지 않는다.
- UF-22의 복구 영역은 같은 준비 작업에서 재렌더링해도 펼침 상태를 보존한다. 다른 준비 작업에는 상태를 넘기지 않는다.
- 준비 응답은 DOM 수신, 전달, 실제 저장, 재시작 후 복원에서 원문 일치를 계속 검사한다. 현재 UI에서 실제 다운로드한 로그에서도 같은 전송의 응답을 검사한다. 통제된 응답에는 자격 증명이 없으므로 원문 그대로 비교하며, 내보내기가 저장 원문을 변경하지 않는지도 확인한다.
- 전송 복구 픽스처는 현재 소유권 확인 UI와 최종 폐기 영수증을 사용한다. 응답 저장 근거가 있으면 폐기할 수 없다는 대조도 유지한다.
- HTTP 전체 제한은 기존 5초다. 별도로 실제 서버의 runtime 읽기 구간을 계측하여 설정한 100ms와 700ms가 적용되는지 검사한다. 준비 초기화 시간은 이 계측에서 제외한다. 판정 허용 지연은 500ms이며 기본 4초로 설정을 무시하면 두 검사 모두 실패해야 한다.
- 정상 응답성 검사에는 해당 요청 이후 수신한 실제 heartbeat의 event-loop 지연 검사를 추가한다. IPC 무응답 경고만으로 CPU 정지를 확정하지 않으며, 기존 CPU 정지 반례와 독립 HTTP 응답 제한도 유지한다.
- `test:browser`는 기존 브라우저 네 파일과 팝업 화면 검사를 모두 실행한다. `verify:all`은 새 GUI 완료 기록이 없으면 통과시키지 않는다.
- 네이티브 검사는 실제 확장 다운로드, Chrome 창 생성·API 크기 변경, 정확한 소유권 필드 전후 비교와 전송 없음까지 검사한다. 완료 게이트는 개수 5를 임의로 요구하지 않고 명시된 일곱 경계의 고유 ID와 성공을 확인한다. 누락·중복·실패·미완료는 거절한다.

## 검증 경계

Chromium의 DOM 픽스처 검사는 실제 ChatGPT나 Windows 창 관리자 조작의 근거가 아니다. 네이티브 검사의 창 크기 변경도 API 검사이며 사용자의 테두리 드래그 자체를 자동화하지 않는다.

사용 가능한 Linux Chromium에서는 확장 service worker를 관측하지 못해 네이티브 실행은 `UNVERIFIED`다. 이 결과를 통과로 처리하지 않는다. Windows의 실제 확장 검사와 전체 검사는 별도 실행해야 한다.

이 패치는 Windows 코드 이력 HTTP의 watchdog 경고와 verification lifecycle의 EBUSY/종료 코드 null을 해결했다고 주장하지 않는다. 해당 제품·픽스처 원인을 확정하지 않은 상태에서 시간 제한이나 기대 종료 값을 완화하지 않는다. 기존 Git 경로 별칭·shallow clone 패치는 이 UI 검증 패치에 합치지 않는다.

## 전체 검사와 최신 로그

패치를 적용한 저장소 루트의 PowerShell에서:

```powershell
npm run verify:all; notepad .agent-controller/latest-verification.log
```

기존 최신 로그 파일을 덮어쓴다. 최종 FAIL 또는 PARTIAL을 Windows 완료로 해석하지 않는다.
