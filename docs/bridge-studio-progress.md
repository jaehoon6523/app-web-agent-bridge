### ST-11·ST-12 남은 검증과 완료 기준

기존 증거는 Controller의 시간 초과·수동 재시도 회귀와 합성 상태의 화면 비교다. 남은 검증은 브라우저에서 실제 Controller 상태 전이와 화면의 관측·복구 동작을 함께 확인하는 것이다. 기존 운영 기록은 읽기 전용으로 관찰하고, 실패 주입과 실제 재시도는 격리 프로젝트에서 수행한다.

- **ST-11 실행 관측.** Worker가 시작되어 현재 turn의 활동이 들어옴 → 실행 상태와 해당 turn의 활동이 표시된다. 관측이 없거나 이전 turn의 활동만 있음 → 최신 활동 미확인을 표시한다. 대화형 Worker의 활동 또는 입력 대기 상태는 Controller가 제공하는 경우 그 상태에 맞게 표시한다.
- **ST-11 실패 표시.** 실행 중 Worker가 실패하거나 시간 초과됨 → 현재 turn의 원인과 실패 또는 복구 필요 상태가 표시된다. 고정 후보가 있으면 그 ID가 표시되고, 없으면 고정 후보 없음이 표시된다. 갱신 후에도 이전 turn의 오류를 새 turn의 오류로 표시하지 않는다.
- **ST-12 재시도 허용.** 후보 고정 전 실패, 종료 확인, Controller가 `run.retry` 허용 → 재시도 버튼과 다음 행동이 표시된다. 사용자가 한 번 누르면 요청이 한 번만 전달되고 같은 승인 요구사항으로 새 Worker turn이 시작된다. 새 turn과 이전 실패 기록을 구분할 수 있다.
- **ST-12 재시도 차단.** 종료 미확인, 고정 후보 존재 또는 재시도 권한 없음 → 차단 이유와 해당 상태에서 허용된 조치가 표시된다. 새로고침과 늦은 이벤트만으로 Worker가 다시 시작되지 않는다. 조회 후 버전이 바뀌면 오래된 요청이 거절되고 최신 상태가 표시된다.

- **ST-11 활동 미확인**. 격리 브라우저에 실제 실행의 상태 응답을 제공하면서 `workerRuntime`만 비운 응답을 재현했다. 실행은 유지되고 Worker 콘솔에 최신 활동 미확인이 표시됐다. 이 분기는 브라우저 응답 주입으로 검증했다.
- **ST-11 대기 상태**. 현재 turn에 Codex 도구 승인 요청을 주입했다. 실제 Controller가 `APPROVAL_WAIT`를 반환했고 브라우저에 “Codex 승인 대기”가 표시됐다. 별도의 자유 입력을 요청하는 Worker 프로토콜·UI 경로는 현재 구현에서 확인되지 않아 일반 사용자 입력 대기는 미확인이다.
- **ST-12 지연 이벤트**. 수동 재시도 후 새 Worker 프로토콜 연결에 이전 turn ID의 지연 실패 이벤트를 보내고 이어서 새 turn의 도구 시작을 보냈다. Controller가 새 turn 도구 활동을 반영한 뒤에도 같은 새 turn이 실행 중이고 복구 이력 및 브라우저의 `run.retry` 요청은 각 한 건이었다. 이전 오류는 다시 표시되지 않았다.
- 대시보드·모델 회귀 88건과 확장된 격리 브라우저 시나리오 1건 통과. 운영 기록에는 변경 명령을 보내지 않았다. 동일 SHA 통합 검증은 별도다.
